# CS 250 Portfolio

## Sprint Review and Retrospective: SNHU Travel Project

This repository includes my CS 250 portfolio artifact, the Sprint Review and Retrospective for the SNHU Travel project. In this project, I reflected on how Scrum-Agile helped support the software development process, including Scrum roles, user stories, communication, interruptions, organizational tools, and the overall effectiveness of Agile compared to waterfall development.

## Portfolio Artifact

- Sprint Review and Retrospective: SNHU Travel Project

## Reflection

### How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I interpret user needs by thinking about what the user is trying to accomplish and what problem the program should solve for them. Instead of only focusing on the technical side, I try to understand the user’s goal first. User stories help with this because they describe a feature from the user’s point of view. They make it easier to understand why a feature matters and how it should provide value. For the SNHU Travel project, user stories helped break the project into smaller pieces so the team could focus on features that would make trip planning easier and more useful for customers.

### How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I approach developing programs by breaking the work into smaller steps, understanding the requirements, planning the main features, and then improving the program through testing and feedback. Agile helped me see that software development does not have to be completed all at once. It can be built in smaller parts, reviewed, and improved over time. In the future, I hope to use Agile processes such as sprint planning, daily communication, product backlogs, user stories, sprint reviews, and retrospectives. These processes help keep the work organized and make it easier to adjust when requirements change.

### What does it mean to be a good team member in software development?

Being a good team member in software development means communicating clearly, being reliable, helping solve problems, and staying open to feedback. A good team member does not only focus on their own task but also understands how their work affects the rest of the team. In Scrum, teamwork is important because the Product Owner, Scrum Master, developers, and testers all contribute to the success of the project. Good team members support each other, share updates, ask questions when something is unclear, and work together toward the project goal.

## Conclusion

This project helped me understand how Scrum-Agile supports teamwork, flexibility, communication, and continuous improvement. The SNHU Travel project showed me that Agile is useful when a project needs to respond to changing needs while still keeping the user at the center of development.
